# 桥接实盘指南

xxybacktest 的实盘账户支持两种后端对接 QMT 真实账户：**miniQMT 直连** 与 **大QMT 桥接**。两者提交一次后，由账户记录里的 `qmt_mode` 自动决定每次定时任务走哪条路，你无需改代码。

## 两条路线怎么选

| 对比 | miniQMT 直连 | 大QMT 桥接 |
|------|-------------|-----------|
| 适合场景 | 本机装了 miniQMT 客户端 | 本机无 miniQMT / 大QMT 独占运行 |
| 原理 | 直接用真·xtquant 连本地客户端 | 内置"桥接替身包"经 ZMQ 转发给大QMT 服务端 |
| 配置复杂度 | 简单：填 `qmt_path` | 中等：需部署桥接服务端 + 填账号 |
| 下单接口 | 标准 xtquant（成熟稳定） | 自定义桥接转发（已实测） |
| 端口依赖 | 无 | ZMQ 端口（`15560 + 账号末两位`） |

## 路线一：miniQMT 直连

### 前置条件
- 本机已安装 miniQMT 客户端（如国金 QMT 的 `userdata_mini`）
- 客户端已登录

### 提交实盘账户

```python
from xxybacktest.simulation import submit

account_id = submit(
    name="茅台实盘策略",
    initialize=initialize,
    handle_data=handle_data,
    account_type="live",
    live_account_id="8881686799",                       # QMT 资金账号
    qmt_path=r"D:\国金证券QMT交易端\userdata_mini",       # miniQMT 安装目录
    trigger_cron="30 9 * * *",
    asset_type="stock",
    data_path="./data",
)
```

### 验证（只读）
启动服务后，系统每天按 `trigger_cron` 自动连 miniQMT 读取持仓/资金、跑策略。首次建议先用空策略跑一次，确认连接与读数正常，再放开下单。

## 路线二：大QMT 桥接

### 原理（一句话）
本机没有 miniQMT、或想用大QMT 时，xxybacktest 内置一个"桥接替身包"（同名 `xtquant`），把策略里的下单/查询调用通过 ZMQ 转发给**运行在大QMT 里的服务端进程**，由服务端真正下单。

### 端口公式
桥接服务端端口 = `15560 + (资金账号末两位)`。

| 账号 | 末两位 | 端口 |
|------|--------|------|
| `8881686799` | 99 | **15659** |
| `1234567890`（示例） | 90 | 15650 |

### 步骤 1：服务端部署（在大QMT 端）
1. 把 `bridge_client/server/` 下的文件复制到 QMT 客户端的 `python` 目录（如 `D:\国金证券QMT交易端\python\`）。
2. 编辑 `bigqmt_signal_trader_local_config.py`：填你的资金账号、端口（按上面公式）、`rpc_allow_order_methods: True`（下单总开关）。
3. 在 QMT 客户端里运行 `BIGQMT_ZMQ_DRYRUN.py`，服务端启动并监听端口。

> ⚠️ 该配置文件含你的真实账号，已被 `.gitignore` 忽略，**不要提交到公开仓库**。

### 步骤 2：客户端配置
1. 编辑 `bridge_client/client/bigqmt_signal_trader_client_config.py`：填资金账号、端口（与服务端一致）。
2. 该文件同样含账号，已被 `.gitignore` 忽略，勿提交。

### 步骤 3：提交实盘账户（指定桥接模式）

```python
from xxybacktest.simulation import submit

account_id = submit(
    name="茅台实盘策略(QMT桥接)",
    initialize=initialize,
    handle_data=handle_data,
    account_type="live",
    live_account_id="8881686799",
    qmt_mode="QMT",            # 关键：走大QMT 桥接（默认是 miniqmt）
    trigger_cron="30 9 * * *",
    asset_type="stock",
    data_path="./data",
)
```

### 验证（只读）
确认大QMT 客户端已打开、桥接服务端在跑（端口 OPEN），再用空策略跑一次 `run_live`，看是否经桥接读回资金/持仓。

## 切换后端
已提交的账户，用 `update_account` 改 `qmt_mode` 即可切换，无需重建：

```python
from xxybacktest.simulation import update_account
update_account(account_id, qmt_mode="miniqmt")   # 切回直连
```

## 风险提示
- **实盘下单前请务必先用 100 股小单验证**「下单 → 回报 → 撤单」整条链路。
- 桥接服务端的 `rpc_allow_order_methods` 默认开启，意味着任何能连上端口的程序都能下单——仅在可信环境部署。
- 所有回测 / 模拟结果均为研究用途，不等于实盘收益。

## 常见问题
- **关掉大QMT 后还有后台线程？** 早期版本桥接客户端 `stop()` 未级联清理传输层线程，现已修复（`bridge_client/client/bigqmt_signal_trader/xtquant_compat.py` 的 `stop()` 现会彻底收口）。如仍遇到文件被占，多为 VS Code 里打开过的 notebook 内核未关，关掉内核再删即可。
