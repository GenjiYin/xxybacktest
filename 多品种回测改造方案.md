# xxybacktest 多品种多账户回测改造方案

> 版本: v0.1  
> 日期: 2026-06-05  
> 目标: 在保留现有单账户回测能力的前提下，支持一个回测实例内管理多个账户（如股票账户 + 基金账户），实现真正的多品种策略回测。

---

## 一、设计目标

| 目标 | 说明 |
|------|------|
| 多账户 | 一个 `run_backtest()` 内可创建并管理多个独立账户，如股票账户 + 基金账户 |
| 多品种 | 不同账户可配置不同 `asset_type`（stock / fund），各自加载对应数据、走对应规则链 |
| 向后兼容 | 现有单账户策略代码**零改动**即可运行 |
| 资金隔离 | 各账户资金、持仓、订单、绩效完全隔离 |
| 统一视图 | 支持分账户查看绩效，也支持按资金加权汇总整体绩效 |

---

## 二、核心设计：Account 账户模型

### 2.1 Account 类

新增 `objects.py`（或独立 `account.py`）中的 `Account` 类，将原先分散在 `context` 根层的账户相关字段全部收拢：

```python
class Account:
    """
    单个回测账户的完整状态容器。
    原先 context.portfolio / context.account(费率) / context.logs / context.performance
    全部下沉到 Account 实例中。
    """

    def __init__(self, account_id, asset_type, capital, order_cost=None, slippage=None):
        self.account_id = account_id          # 唯一标识，如 "stock_main"
        self.asset_type = asset_type          # "stock" | "fund"

        # ---------- 费率配置（原 context.account） ----------
        self.open_tax = 0
        self.close_tax = 0.001
        self.open_commission = 0.0003
        self.close_commission = 0.0003
        self.min_commission = 5
        if order_cost is not None:
            self.open_tax = order_cost.open_tax
            self.close_tax = order_cost.close_tax
            self.open_commission = order_cost.open_commission
            self.close_commission = order_cost.close_commission
            self.min_commission = order_cost.min_commission
        elif asset_type == "fund":
            self.close_tax = 0  # 基金无印花税

        # ---------- 滑点配置（原 context.trade.slip） ----------
        self.slip = 0
        self.sliptype = "pricerelated"
        if slippage is not None:
            self.slip = slippage.value
            self.sliptype = slippage.type

        # ---------- 规则链（原 context.trade.rule_list） ----------
        if asset_type == "stock":
            self.rule_list = "rule_stop,rule_limit,rule_t1,rule_volume_num,rule_cost,rule_100,rule_volume_ratio,rule_delist"
        elif asset_type == "fund":
            self.rule_list = "rule_stop,rule_limit,rule_t1,rule_volume_num,rule_cost,rule_100,rule_volume_ratio"
        else:
            raise ValueError(f"unsupported asset_type: {asset_type!r}")

        # ---------- 订单成交量限制（原 context.trade.order_volume_ratio） ----------
        self.order_volume_ratio = 1.0

        # ---------- 资金与持仓（原 context.portfolio） ----------
        self.portfolio = DictObj({
            "cash": capital,
            "total_value": capital,
            "previous_value": capital,
            "starting_cash": capital,
            "positions_value": 0,
            "positions": {},
            "locked_cash": 0,
        })

        # ---------- 日志（原 context.logs，按账户隔离） ----------
        self.logs = DictObj({
            "order_list": [],
            "trade_list": [],
            "trade_returns": [],
        })

        # ---------- 绩效（原 context.performance，按账户隔离） ----------
        self.performance = DictObj({
            "returns": [],
            "position_ratio": [],
            "position_snapshots": [],
            "win": 0,
            "trade_num": 0,
            "indicators": {},
            "win_ratio": 0.0,
        })

    # 快捷属性：兼容现有代码中直接访问 account.positions / account.cash 的习惯
    @property
    def positions(self):
        return self.portfolio.positions

    @property
    def cash(self):
        return self.portfolio.cash

    @property
    def total_value(self):
        return self.portfolio.total_value
```

### 2.2 为什么把 rule_list / slip / order_volume_ratio 也收到 Account 里？

因为不同品种的交易规则天然不同：
- 股票有 `rule_delist`（退市拦截），基金没有
- 股票和基金的费率结构不同
- 未来可能支持美股（T+0，无涨跌停），规则链又会不同

把规则链挂在 Account 上，Rules 引擎执行时只需读 `account.rule_list`，无需再访问 `context.trade.rule_list`。

### 3.3 add_account 接口

在 `create_context()` 中或 `initialize` 前将 `add_account` 绑定到 context：

```python
def add_account(account_id, asset_type="stock", capital=0, order_cost=None, slippage=None):
    """
    在回测实例中新增一个账户。

    参数:
        account_id:  账户唯一标识，如 "fund_account"
        asset_type:  "stock" | "fund"
        capital:     初始资金
        order_cost:  OrderCost 实例（可选）
        slippage:    Slippage 实例（可选）

    返回:
        Account 对象
    """
    if account_id in context.accounts:
        raise ValueError(f"account_id '{account_id}' 已存在")

    acc = Account(account_id, asset_type, capital, order_cost, slippage)
    context.accounts[account_id] = acc

    # 如果是首个非默认账户，可能需要触发对应 asset_type 的数据预加载
    # （详见第五节数据层改造）
    Data.ensure_preloaded(asset_type, context.trade.start_time, context.trade.end_time)

    return acc

context.add_account = add_account
```

### 3.4 辅助接口

```python
def get_account(account_id=None):
    """获取指定账户；account_id=None 时返回主账户。"""
    if account_id is None:
        account_id = context.main_account_id
    return context.accounts[account_id]

context.get_account = get_account
```

原代码在 `run_backtest` 中把交易函数绑定到 context：

```python

# 改造后：增加 account_id 参数，默认 None

```

### 4.3 Rules 引擎改造

`Rules.__init__` 需要知道当前订单属于哪个账户：

```python
class Rules:

        self.context = context
        self.account = context.get_account(account_id)   # 关键改动

    def apply(self):
        # 原：rule_list_str = context.trade.rule_list
        # 新：
        rule_list_str = self.account.rule_list
        ...

        # 原：cash = context.portfolio.cash
        # 新：

        ...
```

## 五、数据层改造

### 5.1 问题：现有 run_backtest 只支持单 asset_type 预加载

```python
# 改造前：根据 asset_type 二选一
if asset_type == "fund":
    Data.preload_fund_daily(start_date, end_date)
    Data.preload_fund_dividend(start_date, end_date)
else:
    Data.preload_daily(start_date, end_date)
    Data.preload_dividend(start_date, end_date)
```

### 5.2 改造方案：懒加载 + 标记位

Data 模块增加 `asset_type` 维度的加载标记：

```python
class Data:
    _preload_flags = {"stock": False, "fund": False}

    @classmethod
    def ensure_preloaded(cls, asset_type, start_date, end_date, calendar=None):
        """如果该 asset_type 的数据尚未预加载，则执行加载。"""
        if cls._preload_flags.get(asset_type):
            return

        if asset_type == "fund":
            cls.preload_fund_daily(start_date, end_date)
            cls.preload_fund_dividend(start_date, end_date)
            if calendar:
                cls.preload_fund_split(start_date, end_date, calendar)
        elif asset_type == "stock":
            cls.preload_daily(start_date, end_date)
            cls.preload_dividend(start_date, end_date)
        else:
            raise ValueError(f"unsupported asset_type: {asset_type!r}")

        cls._preload_flags[asset_type] = True
```

### 5.3 run_backtest 中的调用调整

```python
# 改造前
Data.init_db(data_path, asset_type=asset_type)

# 改造后：init_db 不再需要 asset_type，或支持同时连接多库
Data.init_db(data_path)

# 主账户（默认账户）的数据预加载
Data.ensure_preloaded(asset_type, start_date, end_date, calendar)

# 后续用户在 initialize 中调用 add_account 时，再按需触发其他 asset_type 的预加载
```

### 5.4 get_daily_info / get_price 是否需要改造？

**不需要**。数据缓存结构 `_daily_cache` 是 `{date: {code: info}}`，不同品种的代码天然不重复（如 `000001.SZ` vs `000001.OF`），可以共存于同一缓存中。

### 5.5 分红/拆分缓存的共存问题

分红缓存 `_dividend_reg_cache` 目前只区分 pay_date，不区分品种。由于不同品种的分红数据结构一致（都有 `stk_div` / `cash_div_tax` / `pay_date`），可以直接共存。基金拆分虽然结构不同，但存储在同一个 `dividend` dict 中（key 是 `dt_YYYY-MM-DD`），**注意 key 冲突**：

> 如果同一只基金在同一天既有分红又有拆分，目前代码在 `backtest.py` 的 F3 预加载阶段已经做了合并处理（`existing_stk` 合并逻辑），该逻辑在多账户场景下依然适用，因为合并是基于 code 级别的。

### 5.6 新增：按账户查询分红/拆分

分红/送股/拆分的处理在 `backtest.py` 的内置事件处理器中。多账户场景下，事件处理器需要遍历所有账户，按账户的 asset_type 分别处理：

```python
def _before_market(ctx):
    for acc in ctx.accounts.values():
        # 盘前刷新 enable_amount（所有账户都做）
        for code, pos in acc.portfolio.positions.items():
            pos.enable_amount = pos.amount

        # 送股处理：只在 stock 账户执行（基金目前无送股，但拆分的处理逻辑已涵盖）
        # 注意：ctx.data.dividend 中混合了 stock 和 fund 的数据
        # 由于 code 不会跨品种重复，直接遍历 acc.portfolio.positions 即可
        if acc.asset_type == "stock":
            now_date = ctx.current_dt.strftime("%Y-%m-%d")
            dt_key = "dt_" + now_date
            if dt_key in ctx.data.dividend:
                for code, pos in acc.portfolio.positions.items():
                    if code in ctx.data.dividend[dt_key]:
                        # 送股结算（原逻辑）
                        ...
```

> **关键洞察**：由于不同品种代码空间不重叠（股票后缀 .SZ/.SH，基金后缀 .OF/.SH 等），同一个 `dt_key` 下的分红记录按 code 查找时不会"串台"。因此事件处理器只需遍历每个账户的持仓，到共享的 `ctx.data.dividend` 中查找即可，无需按品种隔离缓存。

## 六、事件系统改造

### 6.1 事件处理器从"单账户"改为"多账户遍历"

所有内置事件处理器（`_before_market`、`_morning_start`、`_after_market`、`_end_interval`）需要从操作单个 `context.portfolio` 改为遍历 `context.accounts.values()`。

**以 `_end_interval` 为例**：

```python
def _end_interval(ctx):
    for acc in ctx.accounts.values():
        positions_value = 0
        for code, pos in acc.portfolio.positions.items():
            price = Data.get_price(code, ctx)
            if price is not None:
                pos.total_value = pos.amount * price
                pos.last_sale_price = price
            positions_value += pos.total_value

        acc.portfolio.positions_value = positions_value
        acc.portfolio.total_value = acc.portfolio.cash + positions_value

        # 记录该账户当日净值比
        if acc.portfolio.previous_value != 0:
            daily_return = acc.portfolio.total_value / acc.portfolio.previous_value
        else:
            daily_return = 1.0

        date_str = ctx.current_dt.strftime("%Y-%m-%d")
        acc.performance.returns.append([date_str, daily_return])

        # 持仓占比 / 持仓快照 同理，都写入 acc.performance
        ...

        acc.portfolio.previous_value = acc.portfolio.total_value
```

### 6.2 用户策略事件（run_daily / handle_data）

用户策略函数中可以自由操作任意账户：

```python
def handle_bar(context):
```

## 八、绩效计算改造

### 8.1 分账户绩效

`Performance.analyse` 需要支持传入单个 account：

```python
class Performance:
    @staticmethod
    def analyse_account(account, context, benchmark_returns=None):
        """计算单个账户的绩效指标。"""
        raw = pd.DataFrame(account.performance.returns, columns=["trade_date", "returns"])
        # ... 同现有逻辑
        indicators = Performance._compute_indicators(
            returns, benchmark_returns, account
        )
        account.performance.indicators = indicators

    @staticmethod
    def analyse(context):
        """计算所有账户的绩效，同时生成汇总绩效。"""
        benchmark = context.trade.benchmark
        bench_returns = Performance._get_benchmark_returns(benchmark, context)

        # 1. 逐个账户计算
        for acc in context.accounts.values():
            Performance.analyse_account(acc, context, bench_returns)

        # 2. 汇总绩效：按资金加权的日收益率
        all_returns = []
        for acc in context.accounts.values():
            df = pd.DataFrame(acc.performance.returns, columns=["trade_date", "returns"])
            df["trade_date"] = pd.to_datetime(df["trade_date"])
            df = df.set_index("trade_date")
            df["total_value"] = _reconstruct_total_value(df["returns"], acc.portfolio.starting_cash)
            all_returns.append(df)

        if all_returns:
            merged = pd.concat(all_returns, axis=1, keys=context.accounts.keys())
            # 合并逻辑：每日总资金加权
            total_starting = sum(acc.portfolio.starting_cash for acc in context.accounts.values())
            # ... 计算 merged_returns 序列
            context.performance.returns = merged_returns - 1
            context.performance.indicators = Performance._compute_indicators(
                merged_returns - 1, bench_returns, context
            )
```

### 8.2 汇总收益率的计算方式

**推荐方式：资金加权日净值比**

```python
def _compute_aggregate_returns(accounts):
    """
    汇总多个账户的日收益率。
    方式：每日按各账户 total_value 加权计算组合净值比。
    """
    # 收集所有账户的 returns DataFrame
    dfs = []
    for acc in accounts.values():
        df = pd.DataFrame(acc.performance.returns, columns=["date", "return_ratio"])
        df["date"] = pd.to_datetime(df["date"])
        df = df.set_index("date")
        df["nav"] = df["return_ratio"].cumprod() * acc.portfolio.starting_cash
        dfs.append(df[["nav"]])

    merged = pd.concat(dfs, axis=1)
    merged.columns = accounts.keys()

    # 每日汇总 total_nav / total_starting
    total_starting = sum(acc.portfolio.starting_cash for acc in accounts.values())
    merged["total_nav"] = merged.sum(axis=1)
    merged["aggregate_ratio"] = merged["total_nav"] / total_starting

    return merged["aggregate_ratio"]
```

> 注意：这种汇总方式假设各账户的收益波动相互独立，且资金在回测期间没有跨账户划转。如果存在 `inout_cash` 跨账户操作，汇总逻辑会更复杂，建议第一期不做跨账户资金划转支持。

### 9.1 现有模拟服务架构回顾

## 十三、边界情况与风险

### 13.1 代码空间重叠风险

> **问题**：如果未来支持美股或港股，代码格式可能与 A 股重叠（如 `AAPL` vs `AAPL.SZ` 这种极端情况）。
>
> **对策**：在 Account 中增加 `market` 字段（`CN` / `US` / `HK`），Data 层的缓存按 `market` 隔离，或强制要求代码带完整后缀。

### 13.2 分红缓存 key 冲突

> **问题**：如果同一只 code（理论上不可能，因为 stock 和 fund 的 code 空间不重叠）在同一天既有股票分红又有基金拆分，F3 预加载的合并逻辑可能出错。
>
> **对策**：目前在 A 股市场此情况不可能发生（同一代码不可能既是股票又是基金）。未来如支持跨市场，需在 `ctx.data.dividend` 的 key 中增加 market 前缀。

### 13.3 绩效汇总的准确性

> **问题**：如果用户在回测过程中通过 `inout_cash` 改变某个账户的资金，资金加权的汇总收益率会失真。
>
> **对策**：第一期 `inout_cash` 仅支持单账户内部出入金，不支持跨账户划转。汇总绩效计算时，使用 `starting_cash` 作为固定权重。更精确的汇总需要支持"动态资金加权"或"组合净值法"，可作为后续优化。

### 13.4 T+1 规则的跨账户影响

> **问题**：如果用户在股票账户买入某 ETF，同时在基金账户买入同一只 ETF（假设允许），T+1 规则是独立的，因为账户隔离。
>
> **对策**：每个账户的 `enable_amount` 独立管理，自然隔离，无需额外处理。

### 13.5 数据预加载的内存开销

> **问题**：同时加载股票 + 基金全量日线数据，内存翻倍。
>
> **对策**：`Data._daily_cache` 中股票和基金的数据结构相同，只是 key 不同，内存开销主要是数据条数增加。如内存受限，可考虑"按需懒加载"（只加载持仓涉及的 code），但这会破坏现有的 O1 优化。建议先实测内存占用，如超过 8GB 再考虑分片加载。

### 13.6 run_backtest 参数语义变化

> **问题**：`asset_type` 参数原来决定整个回测的品种，改造后它只是主账户的默认品种。是否会让用户困惑？
>
> **对策**：保持 `asset_type` 参数语义不变（决定主账户品种），文档中说明"多账户通过 `context.add_account` 创建"。

## 十五、一个关键决策点

**问题：是否支持一个账户内混持不同 asset_type？**

例如：一个 "mixed" 账户，既买 `000001.SZ`（股票）又买 `510300.SH`（ETF，按 fund 处理？）。

**建议：不支持。**

理由：
1. A 股市场中，ETF/LOF 虽然交易在场内，但分红/拆分规则和股票不同，混在一起会让规则引擎难以判断该走哪条规则链。
2. 更简单清晰的模型是：一个账户对应一个品种，多品种 = 多账户。
3. 实盘层面，股票账户和基金账户（如场内基金账户）本身就是分开的。

如果用户想同时持有股票和 ETF，应该创建两个账户：
- `stock_account`（asset_type="stock"）
- `fund_account`（asset_type="fund"）

## 附录：资金池共享设计修正

> 用户反馈：如果 `add_account` 指定了独立资金量，资金比例就被定死了（如股票50万、基金50万）。但实际策略可能需要某天把100万全仓挪到基金上。
>
> 修正：Account 不再持有独立资金池，所有品种共享 `run_backtest` 中传入的 `capital`。Account 的角色从"资金容器"退化为"规则+日志+持仓标记分类器"。

### A.1 Account 类修正

```python
class Account:
    """
    品种账户：不持有独立资金，只负责规则链、费率、日志、绩效分类。
    所有结算统一走 context.portfolio（共享资金池）。
    """

    def __init__(self, account_id, asset_type, order_cost=None, slippage=None):
        self.account_id = account_id
        self.asset_type = asset_type

        # ---------- 费率配置 ----------
        self.open_tax = 0
        self.close_tax = 0.001 if asset_type == "stock" else 0
        self.open_commission = 0.0003
        self.close_commission = 0.0003
        self.min_commission = 5
        if order_cost is not None:
            self.open_tax = order_cost.open_tax
            self.close_tax = order_cost.close_tax
            self.open_commission = order_cost.open_commission
            self.close_commission = order_cost.close_commission
            self.min_commission = order_cost.min_commission

        # ---------- 滑点 ----------
        self.slip = 0
        self.sliptype = "pricerelated"
        if slippage is not None:
            self.slip = slippage.value
            self.sliptype = slippage.type

        # ---------- 规则链 ----------
        if asset_type == "stock":
            self.rule_list = (
                "rule_stop,rule_limit,rule_t1,rule_volume_num,"
                "rule_cost,rule_100,rule_volume_ratio,rule_delist"
            )
        elif asset_type == "fund":
            self.rule_list = (
                "rule_stop,rule_limit,rule_t1,rule_volume_num,"
                "rule_cost,rule_100,rule_volume_ratio"
            )
        else:
            raise ValueError(f"unsupported asset_type: {asset_type!r}")

        self.order_volume_ratio = 1.0

        # ---------- 独立日志（按品种隔离） ----------
        self.logs = DictObj({
            "order_list": [],
            "trade_list": [],
            "trade_returns": [],
        })

        # ---------- 独立绩效（按品种聚合） ----------
        self.performance = DictObj({
            "returns": [],           # 该品种持仓的日净值比序列
            "position_ratio": [],    # 该品种持仓占组合总资产比例
            "position_snapshots": [],
            "win": 0,
            "trade_num": 0,
            "indicators": {},
            "win_ratio": 0.0,
        })
```

**关键变化**：删除了 `portfolio`、`capital`、`starting_cash` 等资金相关字段。

### A.2 add_account 接口修正

```python
def add_account(account_id, asset_type="stock", order_cost=None, slippage=None):
    """
    添加一个品种账户。不指定资金量，所有账户共享主资金池。

    参数:
        account_id:  账户唯一标识，如 "fund"
        asset_type:  "stock" | "fund"
        order_cost:  OrderCost 实例（可选）
        slippage:    Slippage 实例（可选）

    返回:
        Account 对象
    """
    if account_id in context.accounts:
        raise ValueError(f"account_id '{account_id}' 已存在")

    acc = Account(account_id, asset_type, order_cost, slippage)
    context.accounts[account_id] = acc

    # 触发对应 asset_type 的数据预加载
    Data.ensure_preloaded(asset_type, context.trade.start_time, context.trade.end_time)

    return acc
```

### A.4 交易结算流程

```python
def order_buy(code, amount, context, account_id=None):
    account = context.get_account(account_id)  # 获取品种规则+日志容器

    info = Data.get_daily_info(code, context)
    price = Data.get_price(code, context, info=info)
    order = Order(code, amount, is_buy=True, price=price, info=info)

    # 规则引擎使用 account 的规则链和费率
    Rules(order, context, account_id=account.account_id).apply()

    order.date = context.current_dt
    account.logs.order_list.append(order)  # 订单记入品种日志

    if order.status == -1:
        return order

    # ---------- 结算：统一操作 context.portfolio（共享资金池） ----------
    positions = context.portfolio.positions
    if code in positions:
        pos = positions[code]
        pos.total_cost += order.cost + order.amount * order.last_sale_price
        pos.amount += order.amount
        pos.enable_amount += order.enable_amount
        pos.cost_basis = pos.total_cost / pos.amount
        pos.last_sale_price = order.last_sale_price
        pos.total_value = pos.amount * order.last_sale_price
    else:
        pos = Position(
            code=code,
            amount=order.amount,
            enable_amount=order.enable_amount,
            last_sale_price=order.last_sale_price,
            account_id=account.account_id,  # 标记归属
        )
        pos.total_cost += order.cost
        pos.cost_basis = pos.total_cost / pos.amount
        positions[code] = pos

    # 扣款统一走共享资金池
    context.portfolio.cash -= (order.value + order.cost + order.slip_value)
    context.portfolio.positions_value += order.value
    context.portfolio.total_value = context.portfolio.cash + context.portfolio.positions_value

    account.logs.trade_list.append(order)
    return order
```

`order_sell` 同理：卖出回款进入 `context.portfolio.cash`，日志进入 `account.logs`。

### A.5 日终估值流程

```python
def _end_interval(ctx):
    """日终统一估值，再按品种分类记录。"""

    # 1. 统一刷新所有持仓市值
    positions_value = 0
    for code, pos in ctx.portfolio.positions.items():
        price = Data.get_price(code, ctx)
        if price is not None:
            pos.total_value = pos.amount * price
            pos.last_sale_price = price
        positions_value += pos.total_value

    ctx.portfolio.positions_value = positions_value
    ctx.portfolio.total_value = ctx.portfolio.cash + positions_value

    date_str = ctx.current_dt.strftime("%Y-%m-%d")
    total_value = ctx.portfolio.total_value

    # 2. 记录组合级收益率（context.performance）
    if ctx.portfolio.previous_value != 0:
        daily_return = total_value / ctx.portfolio.previous_value
    else:
        daily_return = 1.0
    ctx.performance.returns.append([date_str, daily_return])

    # 3. 按品种账户分别记录持仓和收益
    for acc in ctx.accounts.values():
        acc_positions_value = sum(
            pos.total_value for pos in ctx.portfolio.positions.values()
            if pos.account_id == acc.account_id
        )

        # 品种持仓占组合总资产比例
        if total_value != 0:
            acc_pos_ratio = acc_positions_value / total_value
        else:
            acc_pos_ratio = 0.0
        acc.performance.position_ratio.append([date_str, acc_pos_ratio])

        # 品种持仓快照
        for code, pos in ctx.portfolio.positions.items():
            if pos.account_id != acc.account_id:
                continue
            if total_value != 0:
                ratio = pos.total_value / total_value
            else:
                ratio = 0.0
            cum_return = pos.last_sale_price / pos.cost_basis - 1 if pos.cost_basis != 0 else 0.0
            cum_profit = pos.amount * (pos.last_sale_price - pos.cost_basis)
            # ... name 解析 ...
            acc.performance.position_snapshots.append({
                "date": date_str,
                "instrument": code,
                "name": name,
                "volume": pos.amount,
                "ratio": ratio,
                "cum_profit": cum_profit,
                "cum_return": cum_return,
                "close": pos.last_sale_price,
                "avg_cost": pos.cost_basis,
            })

    # 4. 更新组合级 previous_value
    ctx.portfolio.previous_value = total_value
```

### A.6 绩效计算修正

由于所有账户共享资金池，**组合只有一个统一的收益率序列**。分账户的绩效不是独立的"账户收益率"，而是"该品种持仓在组合中的贡献"。

```python
class Performance:
    @staticmethod
    def analyse(context):
        # 1. 组合级绩效（同现有逻辑）
        raw = pd.DataFrame(context.performance.returns, columns=["trade_date", "returns"])
        raw["trade_date"] = pd.to_datetime(raw["trade_date"])
        raw = raw.set_index("trade_date")
        returns = raw["returns"] - 1

        benchmark = context.trade.benchmark
        bench_returns = Performance._get_benchmark_returns(benchmark, context)

        context.performance.returns = returns
        context.performance.bench_returns = bench_returns
        indicators = Performance._compute_indicators(returns, bench_returns, context)
        context.performance.indicators = indicators

        # 2. 分账户只计算"持仓明细指标"，不另算独立收益率
        # 因为资金共享，各账户没有独立的 cash 流，无法单独算年化/夏普
        # 如需展示，可算：该账户持仓的累计收益贡献、持仓胜率、最大个股回撤等
```

**如果用户确实需要"虚拟独立收益率"**：可以用"资金配额法"——按调仓日各品种的目标仓位比例，虚拟分配资金到各账户，独立跟踪净值。但这会增加复杂度，建议作为 Phase 2 增强功能，不做在核心改造里。

### A.7 分红/送股处理修正

事件处理器统一遍历 `ctx.portfolio.positions`，按 `pos.account_id` 找到对应 account，现金入账到共享池 `ctx.portfolio.cash`。

```python
def _after_market(ctx):
    now_date = ctx.current_dt.strftime("%Y-%m-%d")

    # 按品种分别查分红（因为接口不同）
    for acc in ctx.accounts.values():
        if acc.asset_type == "fund":
            dividend = Data.get_fund_dividend(ctx)
        else:
            dividend = Data.get_dividend(ctx)

        if dividend:
            for code, pos in ctx.portfolio.positions.items():
                if pos.account_id != acc.account_id:
                    continue
                if code in dividend:
                    # 登记到 ctx.data.dividend（共享缓存）
                    ...

    # 派息日：遍历所有持仓，按 account_id 找到对应品种发放
    dt_key = "dt_" + now_date
    if dt_key in ctx.data.dividend:
        for code, pos in ctx.portfolio.positions.items():
            if code not in ctx.data.dividend[dt_key]:
                continue
            # 现金红利入账共享池
            entry = ctx.data.dividend[dt_key][code]
            if entry.get("preloaded"):
                entry["cash_tax"] = pos.amount * entry["cash_tax_per_share"]
                entry["preloaded"] = False
            if entry["cash_tax"] > 0:
                ctx.portfolio.cash += entry["cash_tax"]
                pos.total_cost -= entry["cash_tax"]
                pos.cost_basis = pos.total_cost / pos.amount
```

### A.8 T+1 / 停牌 / 退市 处理修正

- 退市股检查：`morning_start` 中遍历 `ctx.portfolio.positions`，按 `pos.account_id` 找到对应 account 的 asset_type，股票才检查退市，基金跳过

### A.10 修正总结

| 原设计 | 修正后 |
|--------|--------|
| Account 持有独立 portfolio（cash + positions） | Account 不持有 portfolio，只存规则+日志+绩效 |
| `add_account(..., capital=500000)` | `add_account(...)` 无 capital 参数 |
| 每个账户独立结算 | 统一结算到 `context.portfolio` |
| 分账户独立年化/夏普 | 组合只有一个绩效，分账户只展示持仓明细/胜率/贡献 |
| 多账户间资金划转需特殊处理 | 资金天然共享，无划转概念 |

这个修正使架构更简洁，也更符合用户"资金自由调配"的直觉。所有品种本质上只是"同一组合中的不同持仓类别"，各自走自己的交易规则而已。
